### Worktree and simulator cleanup

**You own the disk and the safety gate.** Prune merged or abandoned git worktrees and stale iOS simulators to reclaim space. Deletion is irreversible, so every step guards against deleting something in use or holding uncommitted or unpushed work.

1. Snapshot and audit. Record `df -h /`, then enumerate with `git worktree list --porcelain` in the main checkout, so every path comes from git and none is hand-typed (principle-build-the-lever, principle-encode-lessons-in-structure). Per path, read size with `du -sh`, tracked and untracked edits with `git status --porcelain`, unpushed commits with `git log @{u}..`, PR state with `gh pr list --head <branch> --state all`, and the newest thread that touched it with `t3_thread_search` on the branch name. `t3_worktree_status` and `t3_worktree_list` describe one thread's workspace, so use them to cross-check a thread's own worktree, not to enumerate the disk. Judge merged against the PR's base ref (`origin/<branch>`), not the default branch, when PRs target another branch. Then bucket each worktree. `safe` is clean, has no unpushed commits, its PR is merged or closed, and no thread touched it lately. `verify-recent-thread` is clean and pushed but a recent thread touched it. `wip:N` has N tracked uncommitted edits. `scratch:N` has N untracked files and no tracked edits. `unpushed` has commits not on its upstream.
2. The bucket is advice, not permission. The pinned and active threads are the real artifact (principle-prove-it-works). Get that set from the user or sidebar and cross-check every candidate. The audit has marked `safe` a worktree the user had pinned, so the pinned set wins.
3. Verify usage before deleting. For every `verify-recent-thread` row, or anything you doubt, fan `delegate_task` workers out with self-contained briefs and `mode: "async"` to read the threads with `t3_thread_read` and `t3_thread_search` and report whether the thread is pinned or ongoing and which worktrees it touches (principle-guard-the-context-window, threads are bulk). Drain with `task_status`. Set each delegate's effort in `target.options`, plus speed (`fastMode` or `serviceTier`) when the model offers it, per the Subagents section. A pinned thread's delegates spawn arena and repro trees into sibling worktrees, and those are in use even when their names never hit the sidebar.
4. Pause on irreversible loss. For `wip:N`, show the diff and get a decision first, since removing a clean worktree is recoverable from its branch but uncommitted work is gone. `scratch:N` is untracked throwaway and safe to drop, but name the files. Per Autonomy, clean and merged and not-in-use proceeds. `wip`, unpushed work, and in-use pause.
5. Prune the confirmed set. Per path, `git worktree remove --force <path>`. If the dir survives on ignored build artifacts, `rm -rf` it, then `git worktree prune`. Branch refs survive, so no commits are lost. Confirm with `df -h /` and re-list with `t3_worktree_list`.
6. Simulators and other reclaimers. Simulators are usually the next-biggest win. Enumerate with `device_list`, then `xcrun simctl --set testing delete all` (XCTestDevices clones), `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` then `runtime delete <id>` for old runtimes. More when needed: Xcode `DerivedData` and `iOS DeviceSupport`, package caches (pnpm, uv, brew, yarn). Clear only caches the user has not said to keep.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which thread, or holding uncommitted or unpushed work).
